  1096→Task ID: footer-scroll-fix
  1097→Agent: main (user-reported bug)
  1098→Task: Fix layout issue — users could scroll past the table and beneath the footer
  1099→
  1100→## Root Cause
  1101→The flexbox scroll chain was missing `min-h-0` on key flex children. In CSS flexbox, flex items have `min-height: auto` by default, which prevents them from shrinking below their content size. This can cause the main content area to grow beyond its parent's height in some browsers, allowing the page to scroll past the footer. Additionally, `html, body` didn't have `overflow: hidden`, so the page itself could scroll.
  1102→
  1103→## Fix
  1104→1. **globals.css**: Added `html, body { height: 100%; overflow: hidden; }` — prevents the page itself from scrolling at all. The content scrolls internally within the `<main>` element.
  1105→2. **app-shell.tsx — middle section**: Added `min-h-0` to the `flex flex-1 overflow-hidden` div. This ensures the middle section can shrink below its content size, allowing proper height bounding.
  1106→3. **app-shell.tsx — right column**: Added `min-h-0` to the `flex min-w-0 flex-1 flex-col` div. Completes the flexbox scroll chain.
  1107→4. **app-shell.tsx — main**: Added `min-h-0` to the `<main className="flex-1 overflow-y-auto">` element. This is the critical fix — `min-h-0` allows the main to shrink and its `overflow-y-auto` to work properly, creating a bounded scroll container.
  1108→5. **app-shell.tsx — footer**: Added `relative z-10` to ensure the footer has a proper stacking context and stays above other content.
